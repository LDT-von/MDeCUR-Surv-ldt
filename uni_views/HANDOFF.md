# 发给有数据那台电脑的接入提示词

请接入这份独立的 UNI 双视图工具，保留现有数据与患者划分。它从原始 WSI 和原坐标重新读取像素，对同一个完整 patch 生成两个 D4 图像视图，再用冻结 UNI v1 提取特征，不随机删 patch，不使用旧槽机制代码。

先完成环境与输入接线、只读 plan/doctor、准备可复核的试运行命令。若用户已经明确授权了具体试运行范围，按该范围继续，不重复索要确认；不要把小范围授权扩展成全量患者提取或生存训练。

1. 阅读 `uni_views/README.md`。本机报告中的目录是线索，不是已再次验证的事实。确认 WSI、坐标、UNI v1 权重的实际绝对路径，确认不是 UNI2-h 或生存模型权重。
2. 根据既有患者—切片映射和 splits 建立 `slides.csv`；不要按文件名猜患者，不静默排除缺失21张WSI涉及的患者。先报告交集/缺失、患者和切片各自数量及受影响划分。保持完整 slide_id（包括实际文件名中的 UUID 部分）。
3. 核实原始提取预处理的证据。默认 JSON 是官方 UNI v1 风格的完整方形 patch → 224，并不证明与下载特征一致。记录实际选定配方。此版只接收 patch_level=0，不自行转换倍率。
4. 在选定 Python 环境执行 plan。若 h5py/Pillow 等缺失，先列出环境及拟安装内容；不得覆盖现有训练环境或擅自升级 PyTorch。确认 CUDA GPU、PyTorch 架构支持和 OpenSlide 原生库；然后执行 doctor（不读 patch、不加载 UNI）。报告原始 WSI 尺寸、MPP、边缘数量及所有错误。
5. 默认边缘策略是 error。若需要白底补齐，说明旧流程是否使用过补齐及差异，再给出带 `--edge-policy pad-white` 的具体命令。禁止跳过或重排边缘行。
6. 准备少量代表性切片、每张前1000个patch的试运行命令，使用新输出目录、`--include-reference`、明确 GPU 和 batch-size。列出两份/三份特征空间、当前空闲磁盘、输入来源和预计显存。用户未给出实际执行范围时，先交付命令与尚缺条件；已有明确授权时按其范围执行。
7. 试运行以后应报告一次完整读图—计算—写入的耗时、images/s、实际显存、输出行数/坐标/变换/特征校验；比较新 reference 与旧缓存时，先有来源对应证据，再谈相似度。不能靠行数相同就认定逐行一致。
8. 当前癌症研究训练接口已支持 `--path-views cached_uni`，要求同文件的 reference+A+B；可选stream后端使用lazy H5、患者batch和checkpointed patch分块，见 `../STREAM_TRAINING.md`。没有三视图时，现成PT只能接入显式的单视图普通融合基线，见 `../SINGLE_VIEW_TRAINING.md`。Tri-Surv 的原 loader 尚未改动，若要接入应另外报告需要修改的具体接口。

请给出：环境和输入检查结果、实际 CSV/配方路径、plan/doctor 输出摘要、待执行的精确试运行命令、仍未验证的项目。不要宣称真实患者效果已验证。
